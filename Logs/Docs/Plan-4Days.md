| 天数 | 主题 | 核心目标 | 结束时能演示什么 |

### ✅ 1.1 中文字体接入（已完成 2026-09-16）

已完成的部分：

1. ✅ 源字体 `Assets/TextMesh Pro/Fonts/Genshin.ttf` → 生成 `Genshin SDF.asset`
2. ✅ `TMP Settings.m_defaultFontAsset` 指向 `Genshin SDF`
3. ✅ `TMP Settings.m_fallbackFontAssets` 挂上 `LiberationSans SDF`（拉丁字符走原字体，排版更精细）

**🔴 剩余唯一一步（需在 Unity 编辑器内操作，约 30 秒）**：

`Genshin SDF.asset` 目前是**静态图集**（`m_AtlasPopulationMode: 0`，只烘焙了 3609 个字形），
实测 `伽 （ ） 「 」 『 』 — · !` 等字符不在图集内，**仍会显示方块**。

1. 选中 `Assets/TextMesh Pro/Fonts/Genshin SDF.asset`
2. Inspector 顶部 `Atlas Population Mode`：**Static → Dynamic**
3. 勾选 `Is Multi Atlas Texture Enabled`
4. `Apply`（`Clear Dynamic Data on Build` 保持**不勾**）

> **勘误**：原文第 4 步"追加中文换行规则"**作废，且映射方向是反的**。TMP 自带的
> `LineBreaking Leading/Following Characters.txt` 已完整覆盖中日文禁则，无需追加任何字符；
> 原文把闭标点写进 `Leading`、开标点写进 `Following`，照做会制造禁则错误。详见 `Design.md` 附录 A.2。
>
> **⚠️ 授权待决策**：`Genshin.ttf` 是米哈游专有字体（客户端提取物），本计划原定的标准是
> "作品集会公开，注意授权"。按同一标准它属于风险项。替换成本极低（只换 TTF 重新生成，
> 代码与场景引用不受影响），合规替代推荐**思源黑体 / Noto Sans CJK**。详见 `Design.md` 附录 A.3。

### 关键决策（不要现场试，直接采用）

- **气泡宽度**：`ContentSizeFitter` **只勾 Vertical**，配合 `LayoutElement.preferredWidth` 上限 clamp。
  ⚠️ 若只勾 Horizontal，TMP 的 `preferredWidth` 取的是**不换行的整行宽度**，长文本气泡会无限变宽撑破面板。
- **跳转用 ID 不用数组下标**：策划增删节点时下标会位移，存档里的旧下标会指向错误节点。
- **Emoji 不单独建 MessageKind**：作为 Text 内嵌 TMP 富文本标签 `明天见 <sprite name="smile">`。工程已有 `EmojiOne.asset` 且 `m_enableEmojiSupport: 1`，**开箱可用**。
- **TimeDivider 作为一种 MessageKind 持久化**，插入时计算一次，避免恢复时重算导致的不一致。
- **消息时间戳由策划配置，不读运行时时钟**：节点上配 `timeLabel`（显示文案）+ `timeValueUtc`（间隔比较）。
  ⚠️ 两个字段缺一不可——**文案无法比较大小，数值无法表达"昨天"**。**未配置时间的消息不显示时间，也不参与分割线判断**。

### ✅ 验收标准

- [ ] 中文显示正常，**无方块**，中文标点换行位置正确
- [ ] 200 字中文气泡正确换行，宽度不超过面板 70%，不截断
- [ ] Emoji 与文字在同一行内正确混排
- [ ] 配置了时间的消息按间隔 > 5 分钟插入分割线；**留空时间的消息不显示时间、也不触发分割线**
- [ ] 滚动列表**无横向滚动**
- [ ] `DialogueRunner` 可在**不进入 Play 模式**下被实例化并驱动（证明无 MonoBehaviour 依赖）

### 📦 产出

## Day 2 —— 交互闭环

> **目标**：点联系人 → 看历史 → 选回复 → 收 NPC 回复，完整闭环。

### 任务清单

| # | 任务 | 预估 | 说明 |
|---|---|---|---|
| 2.1 | 气泡对象池 | 2h | 用 `UnityEngine.Pool.ObjectPool<T>`；池容量 30，按需扩容，**不缩容** |
| 2.2 | 联系人项对象池 | 1h | 同上，容量 10 |
| 2.3 | `ContactListView` | 2.5h | 绑定联系人列表，头像/名字/预览（自适应截断）/红点/选中态；点击切换 |
| 2.4 | `ChatWindowView` | 2h | 加载某联系人历史；切换时**保存/恢复滚动位置**；顶部栏名字+签名绑定 |
| 2.5 | `ReplyOptionsView` | 2h | 动态生成 1~3 个不定数量选项按钮；点击 → 发玩家消息 → 推进节点 → 面板消失 |
| 2.6 | Typing indicator + 发送延迟 | 2h | **两处联动**：顶部签名临时替换为"对方正在输入…" + 列表出现 `...` 三点变色小气泡。⚠️ 三点用 **3 个 `Image` 插值**，禁用 TMP 富文本每帧改写（会触发网格重建） |
| 2.7 | 自动滚底 | 1.5h | 新消息到达滚到底；**玩家手动上滑时不打断**（判断 `verticalNormalizedPosition` 阈值） |
| 2.8 | 多联系人状态管理 | 2h | 见下方关键决策 |

### 关键决策

- **切换联系人时正在播放的延迟消息**：**挂起而非丢弃**。用「每会话一个待执行队列」而非全局定时器，切回来继续倒计时。
- **未读清零时机**：进入聊天即清零（不是滚动到底才清），符合主流 IM 直觉。
- **滚动位置记忆**：按 `contactId` 存 `verticalNormalizedPosition`，切回来恢复。
- **多个联系人同时有延迟消息**：允许并行推进，各自独立计时；但**只有当前激活会话的 UI 更新**，非激活会话的延迟消息静默入队并累加未读。

### ✅ 验收标准

- [ ] 3 个联系人可自由切换，名字/签名/历史全部正确对应
- [ ] 未读红点：收到消息出现 → 进入聊天消失 → 切换别处再回来状态正确
- [ ] 点击选项 → 玩家气泡立即出现 → **顶部签名变"对方正在输入…" + 列表出现 `...` 三点变色气泡** → 延迟后 NPC 回复出现、签名恢复
- [ ] 选项数量为 1 / 2 / 3 时布局均正常，不溢出
- [ ] **收发 500 条消息，Profiler 中 `Instantiate` 调用次数 ≤ 池容量**
- [ ] 玩家上滑浏览历史时，新消息到达**不强制拉到底**

### 📦 产出

`Scripts/View/`（三个 View + Pool）、`Scripts/Runtime/ChatSession.cs`、可玩的完整闭环

## Day 3 —— 持久化 + 策划工具

> **目标**：进度不丢；策划可视化配内容，改完即时生效。

### 任务清单

| # | 任务 | 预估 | 说明 |
|---|---|---|---|
| 3.1 | `SaveService` 序列化 | 2h | Schema 见 `Design.md` §7.1；`JsonUtility` + `saveVersion` 字段 |
| 3.2 | 原子写入 | 1h | 写 `.tmp` → `File.Replace`，防写盘中途崩溃导致存档永久损坏 |
| 3.3 | 损坏兜底 | 1h | try-catch 解析失败 → 备份损坏文件 → 重建空存档，**绝不阻塞启动** |
| 3.4 | 恢复流程 | 2h | 按 `currentNodeId` 恢复进度，历史消息 + 时间分割线重建 |
| 3.5 | 写入时机 | 1h | 收到消息后延迟 1s 合并写盘（防连发高频 IO），退出时立即 flush |
| 3.6 | `DialogueEditor` 自定义 Inspector | 3h | `[CustomEditor]` + `ReorderableList`：增删节点、类型切换（Foldout 条件折叠）、跳转目标**下拉框选择** |
| 3.7 | **数据校验器** | 2h | 断链 / 空引用 / 不可达节点 / Choice 无选项 → 红色警告框 |
| 3.8 | **"从该节点预览"按钮** | 1h | 改写 `entryNodeId`，Play 时从此节点开始 |

### 关键决策

- **编辑器工具用 `ReorderableList`，不做 GraphView**。拖拽节点图至少 16h，4 天内做不完，且收益远低于同等时间的打磨。
- **"数据校验"和"节点预览"是这套工具的价值所在**。策划工具的痛点不是"能不能编辑"，而是"配错了能不能立刻发现"。
- **跳转目标用下拉框，禁止手输字符串** —— 手输字符串是断链的主要来源。

### ✅ 验收标准

- [ ] 收到消息 → 退出 → 重进：消息、当前节点、未读状态**完全恢复**
- [ ] 时间分割线在恢复后**位置正确**
- [ ] 手动把存档 JSON 改成非法字符 → 游戏正常启动并重建存档
- [ ] 编辑器里修改 SO → 无需改代码 → Play 中即时生效
- [ ] 故意配一个断链 → 编辑器**红色警告明确指出是哪个节点**
- [ ] 点"从该节点预览" → Play 后从该节点开始

## ⚠️ 风险与范围裁剪

### 延期时的裁剪阶梯（从下往上砍）

| 顺序 | 砍掉什么 | 损失 |
|---|---|---|
| 1️⃣ 先砍 | 图片消息完整支持（保留 1 张证明） | 小 |
| 2️⃣ 再砍 | 网络头像加载 | 小 |
| 3️⃣ 再砍 | 逐条淡入动画 | 小 |
| 4️⃣ 再砍 | 打字机效果 | 中 |
| 5️⃣ 最后砍 | 编辑器"节点预览"（保留校验器） | 中 |
| 🚫 不可砍 | 存档容错、对象池、数据校验、中文排版正确性 | —— |

**不可砍的理由**：这几项是"工程判断力"的体现，也是作品集区别于教程作业的地方。功能少一个不致命，但存档会崩、中文排版错乱、没有校验工具，会直接暴露完成度问题。

> 注：原为"中文换行规则"。勘误后确认 TMP 自带禁则已正确，该子项不再有工作量；
> **排版正确性作为验收底线仍不可砍**，风险点转移到字体图集覆盖（见任务 1.1）。

### 主要风险

| 等级 | 风险 | 应对 |
|---|---|---|
| 🔴 高 | 中文字体问题拖延 | Day 1 第一件事，卡住立即改用静态图集方案 |
| 🔴 高 | 布局组件从零搭建被低估 | 1.5 节已列全，Day 1 不排其他重活 |
| 🟡 中 | 气泡宽度自适应反复调 | 直接采用 Day 1 既定方案，不现场试验 |
| 🟡 中 | 编辑器工具做成 GraphView | 明令禁止，见 Day 3 |
| 🟡 中 | Day 2 交互闭环超时 | 多联系人并行延迟消息可简化为"仅当前会话推进" |
