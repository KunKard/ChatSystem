# 对话内容编辑指南

> 面向：负责写对话内容的策划。
> 需要的前提：会用 Unity 编辑器，能打开工程、能在 Project 窗口里找到资产。**不需要写代码。**
> 对应的实现：`Assets/Scripts/Editor/DialogueEditor.cs`（Inspector 面板）、`DialogueValidator.cs`（校验规则）。

---

## 1. 一句话模型

一段对话 = 一个 **`ConversationAsset`**，里面是一张 **节点表**。

节点之间靠 **ID** 互相跳转，不靠先后顺序。列表里的排列顺序**只影响你在这里看的可读性**，对游戏运行没有任何影响 —— 想让 A 跳到 B，就在 A 的「下一节点」里选 B 的 ID，A 排在第几行都无所谓。

一条最普通的对话链长这样：

```
[入口] → 消息「在吗」 → 等待 1.2s → 消息「有个事想问你」 → 选择 → ...
                                                              ├─ 选项A → ...
                                                              └─ 选项B → 结束
```

---

## 2. 打开面板

在 Project 窗口里找到 `Assets/GameData/Conversations/` 下的 `Conv_XXX.asset`，**单击选中**，Inspector 就会显示本指南描述的面板。

> 如果看到的是 Unity 默认那几个字段（Contact / Entry Node Id / Nodes 排成一列），说明编辑器脚本没编译成功 —— 看 Console 有没有报错。

### 面板从上到下

| 区域 | 作用 |
|---|---|
| **正在预览**（横幅） | 只在预览中出现，见 §8 |
| **概要行** | `N 个节点` + `N 个错误` / `N 个警告` + 「重新校验」按钮 |
| **联系人** | 这个对话属于谁。**必填**，见 §9 |
| **入口节点** | 打开这个联系人时从哪个节点开始。**必填** |
| **校验结果** | 可折叠的问题清单，有「定位」按钮可跳到出问题的节点 |
| **工具条** | 查找 / 下一个匹配 / ＋添加节点 / 取消选中 |
| **节点列表** | 定高滚动区，点一行选中它 |
| **详情面板** | 编辑选中节点的全部字段 |

## 3. 入口节点 —— 最容易卡住的一步

**「入口节点」就是代码里的 `entryNodeId`。** 面板上这一行右边写着 `= entryNodeId`，报错文案里出现的也是这个名字，两边指的是同一个东西。

它是一个**下拉框**，候选就是你这张节点表里的全部节点。

### 新建资产时的死结，以及它是怎么被拆掉的

新建的 `ConversationAsset` 节点表是空的，此时入口下拉框里**只有「（无 —— 到此结束）」一项** —— 没有任何东西可选。而校验器又在要求你设置入口。两句话各自都对，合起来无解。

**现在的规则：加第一条节点时，它会自动成为入口。** 你不需要回来再选一次。

所以**新建对话的正确顺序是**：

1. 点「＋ 添加节点」
2. 第一条节点自动成为入口 ✅
3. 继续往下加

如果你看到一个空资产，那一行下面会直接写着这句话，不用去翻校验结果。

### 改入口的另外两条路

- 「＋ 添加节点」旁边的下拉框 —— 任何时候都能重选
- **节点详情面板里的「设为入口」按钮** —— 看着某个节点想"就用它开场"时直接点，不用先记住 ID 再滚回顶部

### 「▶ 试跑」

入口右边有个「▶ 试跑」按钮：临时把入口改成当前选中的节点，进 Play 模式看效果，**退出 Play 后自动还原**。用于单独调试中间某一段。

预览期间面板顶部有醒目横幅，退出 Play 自动还原。如果编辑器崩了没还原，重新打开工程时 `[InitializeOnLoad]` 会兜底扫一遍。

> ⚠️ 预览会改写 `entryNodeId`。**看到横幅时不要保存提交**，等退出 Play 还原之后再存。

## 4. 节点列表怎么读

每一行是：

```
#下标  类型  ID      摘要
```

摘要按类型不同：

| 类型 | 摘要显示什么 |
|---|---|
| 消息 | 正文前 16 字；表情/图片则显示资源名 |
| 选择 | 有几个选项 + 第一个选项的文案 |
| 等待 | 秒数 |
| 结束 | 无 |

**为什么要显示摘要**：122 个节点里 `a1` / `a2` / `b1` 这类 ID 毫无辨识度，只显示 ID 的话你得逐个点开才能找到想改的那条。

### 工具条

| 控件 | 作用 |
|---|---|
| 查找 + 下一个匹配 | 在 ID、消息正文、选项文案里做不区分大小写的包含匹配，循环跳转 |
| **＋ 添加节点** | 主路径。新节点默认是「消息」类型，ID 自动分配，延迟 0.5 秒 |
| 取消选中 | 收起详情面板 |

> 列表底部还有一个 `+`，效果一样。工具条上那个是主入口 —— 它在滚动区外面，位置固定。

## 5. 四种节点类型

新加的节点默认是**消息**。类型在详情面板里改。

### 消息 `Message`

| 字段 | 说明 |
|---|---|
| ID | 节点标识，自动分配，可改（见 §7） |
| 消息类型 | 文本 / 表情 / 图片 |
| 发送者 | 谁发的，一般选联系人自己 |
| 正文 | 消息内容 |
| 资源名 | 表情/图片类型才用 |
| 延迟 | 这条消息发出前的等待秒数 |
| 下一节点 | 发完之后跳到哪 |
| 时间配置 | 见 §6 |

**关于「延迟」**：它不是最终等待时间，而是**下限**。实际等待会按正文长度折算（每字 0.05 秒，最少 0.8 秒，最多 4 秒）—— 长消息"打字"得久一点才自然。

**填 `0` 有特殊含义**：表示"立刻发出，且不显示『对方正在输入…』"。如果你只是想让消息出得快一点，填个 `0.2` 而不是 `0` —— 否则会连带把打字指示器关掉。

### 选择 `Choice`

| 字段 | 说明 |
|---|---|
| ID | 同上 |
| 下一个选项 | 每个选项一行，见下 |
| 时间配置 | 玩家做出选择后、这条消息发出前的时间判断 |

每个选项有两个字段：

- **文案** —— 按钮上显示的字。**不能为空**，否则游戏里是个空白按钮
- **下一节点** —— 点了之后跳到哪
- **时间配置** —— 玩家消息同样带时间，也参与分割线判断

> ⚠️ **最多 3 个选项。** 超出 3 个的部分游戏里永远不显示、永远选不到，是死内容（面板会报错）。
>
> ⚠️ **一个选项都不能有也是错误。** 游戏会停在这个节点永久卡死，没有任何出路。

### 等待 `Wait`

纯节奏控制，**自己不发出任何消息**。只有一个「延迟」和一个「下一节点」。

用途是"对方停顿了一下"。它的延迟**不**按字数折算，填多少就是多少。

> 连续的等待节点不要超过 64 个（面板会警告）。

### 结束 `End`

没有任何字段。走到这里对话结束。

> ⚠️ **收尾要用一个 `End` 节点，不要把「下一节点」留空。**
>
> 运行时的确把空 `nextId` 也当作结束，但**校验器会把这种情况判为错误** ——
> 因为它和"忘了连边"长得一模一样，看不出是故意的。
>
> 所以对话的正确收尾是：最后一条消息的「下一节点」指向一个 `End` 节点，
> 由 `End` 节点来结束。

## 6. 时间配置

两个字段配合使用：

| 字段 | 说明 |
|---|---|
| 文案 | 显示出来的样子，如 `昨天 21:30` |
| 时刻 | 一个真实时间点，用 `yyyy-MM-dd HH:mm` 填 |

### 关键认识：绝对时刻没有意义，**差值**才有意义

游戏只拿它跟**上一条带时间的节点**比间隔：

- 间隔 **> 5 分钟** → 插入一条时间分割线
- 间隔 **≤ 5 分钟** → 不插
- 时间**倒退** → 也插一条（并报警告）

所以填 `2026-09-26 21:30` 还是 `2020-01-01 21:30` 都不影响结果，**只要相邻两条的差值对**就行。

面板会在时刻字段旁边**只读**显示「距上一条 +10 分钟 · 会插入时间分割线」—— **这行才是你真正在配的东西**，填的时候看它。

### 三条硬规则

- **两个字段要么都填，要么都不填。** 只填文案不填时刻 → 这行时间不显示、也不参与判断（警告）；只填时刻不填文案 → 时间不会显示在任何地方，更隐蔽（警告）
- 「未配置」开关会**同时清空两个字段**，不产生中间态
- 时间**倒退**会报警告

## 7. 引用完整性：删除和改名

这是两个最容易造成**静默损坏**的操作，工具专门做了处理。

### 删除节点

点详情面板的「删除」后，会弹一个对话框，**列出所有指向这个节点的引用**，然后让你三选一：

| 选项 | 结果 |
|---|---|
| 改接到后继「XXX」 | 所有指向它的引用改为指向它的下一节点 |
| 取消 | 什么都不做 |
| 清空引用（改为结束对话） | 所有指向它的引用清空 —— 走到那里就是对话结束 |

**为什么不能直接删**：删完让校验器事后报一堆断链，问题不是"麻烦"，是你**看不出哪条链原本该连到哪里** —— 那条信息在删除的瞬间就没了。

### 改 ID

在详情面板的「ID」字段里改，回车提交。会弹确认框，列出会受影响的地方：

> 有 3 处引用指向 `s4`，改名后会自动改写。

确认后**改名和改写引用在同一次撤销里完成**。绝不会出现"ID 改了但引用没跟上"的中间态 —— 那个状态下如果编辑器崩了或你按了保存，得到的就是一份满是断链、且断得毫无规律的资产。

**ID 命名规则**：非空、不含空白字符、不能和已有 ID 重复。面板会挡住不合法的输入。

> 💡 ID 旁边的「N 处引用」是实时统计，改名前可以先看一眼这个节点有多重要。

## 8. 跳转目标的下拉框

所有「下一节点」字段一律是**下拉框**，从节点表里选，**禁止手输**。这是设计文档的硬性要求。

下拉框里第一项固定是「（无 —— 到此结束）」。

### 一个刻意的设计：悬空引用不会被静默改掉

如果某个跳转指向的节点已经被删了，下拉框里会**原样列出** `<丢失: xxx>` 并标红，而不是默默重置成「（无）」。

**为什么**：静默重置等于你打开一下面板，断链就被偷偷改掉了，校验器再也报不出来 —— 问题从"看得见"变成"看不见"。

看到 `<丢失: xxx>` 就说明这里断链了，重新选一个正确目标。

## 9. 「联系人」字段

**必填。** 它决定这条对话属于哪个联系人。

如果为空，游戏启动时会**整条跳过**这个资产 —— 游戏里根本看不到这个联系人，而且只在那一个瞬间打一条错误日志，之后毫无痕迹。

点旁边的「选中」按钮可以跳到对应的 `ContactProfile` 资产。

> 📌 联系人还需要在**场景里**被登记才会出现在列表中：`ChatAppController` 组件上有一个「Conversations」列表，按展示顺序排列。**顺序即联系人列表顺序。**
> 这一步在场景文件里，不是资产文件里 —— 新增联系人时别忘了。
>
> 另外，**Play 模式中新增的联系人不会出现**：会话列表在 `Start()` 里只构建一次。改完要退出重进 Play。

## 10. 校验器

改任何东西时，面板会自动重跑校验。概要行显示数量，折叠区里逐条列出。

每条问题都会说清**是什么**、**在哪个节点**、**怎么修**。资产级的问题（比如入口没设）没有具体节点，会标成「资产」并且说明去哪儿改。

### 错误（一定会出问题）

| 触发条件 | 游戏里的后果 |
|---|---|
| 节点 ID 为空 | 索引会跳过它，任何跳转都到不了 |
| 节点 ID 重复 | 运行时只认第一个 |
| 入口为空 / 指向不存在的节点 | 一进去就是空会话 |
| 下一节点非空但不存在 | 对话在此**静默**结束 |
| 消息节点的 message 数据为空 | 这条静默不发 |
| 消息/等待节点的下一节点为空 | 对话在此静默结束 |
| 选择节点的选项列表为空 | **永久卡死**，没有任何出路 |
| 选项的下一节点为空/不存在 | 这个选项点了没反应 |
| 选项文案为空 | 空白按钮 |
| 选项超过 3 个 | 超出的部分是死内容 |
| 联系人字段为空 | `ChatAppController` 整条跳过 |
| 非文本消息的资源名为空 | 数据不完整 |

### 警告（可疑但合法）

| 触发条件 | 说明 |
|---|---|
| 从入口走不到这个节点 | 草稿节点属正常，不影响运行 |
| 有文案但时刻为 0 | 这行时间不会显示，也不参与分割线判断 |
| 有时刻但文案为空 | 时间不会显示在任何地方 |
| 时间倒退 | 比同会话中的前一条早 |
| 连续等待超过 64 个 | 打字指示器的预读会失效 |
| 入口到第一个选择之间超过 1000 个节点 | 载入历史会触发成环保护而中断 |

### 批量校验

改完一批之后，用菜单 **`Tools / ChatSystem / 校验全部对话资产`** —— 把工程里所有对话资产跑一遍，结果打到 Console。

单个资产用内联面板看；这个是"改完一批，确认没弄坏别的"时用。

## 11. 常见问题

**Q：报「没有设置入口节点（entryNodeId 为空）」，但我不知道去哪儿设。**
A：就是面板顶部「联系人」下面那一行，标签写着 `入口节点`、右边写着 `= entryNodeId`。下拉框里选一个。
如果节点表是空的，先点「＋ 添加节点」，第一条会自动成为入口。

**Q：点了「＋ 添加节点」，节点没出来。**
A：看 Console 有没有报错。正常情况点一次就多一行。

**Q：跳转下拉框里出现 `<丢失: xxx>`。**
A：那个节点被删了，这条链断了。重新选一个目标。

**Q：改了 ID，别的地方的跳转会不会断？**
A：不会。确认框里列的引用会一起改写。但**旧的存档**里还存着旧 ID —— 存档指向的节点不存在时，运行时会报错并中断对话。改 ID 前想一下有没有人正在玩。

**Q：加了联系人，游戏里看不到。**
A：三查：① 「联系人」字段填了吗；② `ChatAppController` 的 Conversations 列表里加了吗（**列表顺序 = 显示顺序**）；③ 退出重进 Play 了吗。

**Q：节点在列表里的顺序影响运行吗？**
A：不影响。跳转一律走 ID。顺序只影响你在这里找节点的方便程度。

**Q：列表里找不到某个节点。**
A：用工具条的查找框，支持搜正文和选项文案。
